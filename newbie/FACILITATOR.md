# 다음 수를 생각하는 엔지니어 — 강사 가이드

대상: 공학을 전공한 신입 엔지니어. 공학 실험·캡스톤·설계 과제의 경험을 현업의 설계·시험·검증으로 연결합니다. 기계·전기전자·화공·소프트웨어 등 여러 전공이 함께 듣는 청중을 기준으로 구성했습니다.

## 실행

같은 폴더의 `index.html`을 브라우저로 열면 됩니다. 설치·서버·인터넷 없이 본문과 발표 기능을 사용할 수 있습니다. 출처 링크를 열 때는 인터넷이 필요합니다. 외부 폰트나 라이브러리를 불러오지 않습니다. 이미지가 포함된 `assets/` 폴더를 `index.html` 옆에 유지하세요. 이미지를 누르면 확대되고, 기사 카드에서 원문을 열 수 있습니다.

- ← / → / Space: 슬라이드 이동 (Home: 처음, End: 마지막)
- O: 목차, N: 현재 슬라이드 발표자 노트, Esc: 닫기
- F: 전체 화면, P: 인쇄 / PDF 저장 (브라우저 인쇄 기능)
- 모바일: 좌우 스와이프 또는 하단 화살표
- 주소 끝의 `#10`처럼 슬라이드 번호로 바로 열 수 있습니다.

노트는 현재 화면 위에 뜹니다. 화면 공유 중 비공개 발표자 화면이 아니므로, 이 가이드를 다른 기기에서 보거나 미리 출력해 활용하세요. PDF는 별도 납품 파일이 아니라 브라우저에서 생성할 수 있는 출력 옵션입니다.

## 시간 운영

권장 50~60분. 본문 45장, 출처 부록 4장입니다. 각 사례의 의미와 엔지니어가 취할 행동을 바로 설명하는 강의형 구성입니다. 슬라이드별 노트의 시간은 대략적인 상한이며, 아래 구간별 배분에 맞춰 사례 설명을 조절하세요.

| 구간 | 권장 시간 | 전달할 결론 |
|---|---:|---|
| 도입 | 3분 | AI 활용과 개인의 학습을 함께 설계한다 |
| THE SPEED | 8분 | 발전 속도와 실제 업무 효과를 구별한다 |
| THE QUESTION | 9분 | 직업보다 업무의 구성과 판단 경계를 본다 |
| THE SHIFT | 8분 | 도구 도입을 넘어 업무 흐름을 재설계한다 |
| THE ENGINEER | 9분 | 직접 배우고 시스템을 설계·검증한다 |
| THE HUMAN | 10분 | 근거와 맥락을 평가하고 책임을 설계한다 |
| THE CHOICE | 7분 | 작게 적용하고 전체 성과를 측정한다 |

각 사례는 사실 → 의미 → 실무 원칙 순서로 전달합니다. 청중의 응답을 기다리는 순서는 없습니다. 시간이 부족하면 챕터 구분 장을 짧게 넘기고, 비교 사례의 설명을 핵심 문장으로 줄이세요.

## 진행 원칙

- 사례를 낙관론이나 공포론의 증거로 과장하지 않습니다. 직업의 존속과 개인의 고용 안정은 다릅니다.
- 연구 수치는 시점·표본·조건과 함께 소개합니다. 모델 성능, 사용량, 생산성, 고용 효과를 구분합니다.
- 학습 퀴즈 막대와 METR 원본 도표는 연구 수치입니다. 나머지 흐름도와 표지 바둑 격자는 설명용입니다. 표지는 실제 기보가 아닙니다.
- 회사의 실무·도구·데이터 규정은 별도입니다. 전공별 도구 숙련을 가정하지 않습니다. PR 같은 소프트웨어 용어는 풀어 설명하고, 모터·해석·시험 보고서 사례의 핵심을 가정·단위·원본·검증으로 연결합니다.
- 미래 장면, 운영 원칙, AX의 정의는 강의의 해석·제안임을 구별합니다.

## 청중과 연결하는 설명

- 캡스톤에서 작동한 시제품과 현업에서 반복 검증한 제품 사이의 차이를 설명합니다.
- 모터 시험, 시뮬레이션 경계조건, 단위 변환, 시험 보고서로 엔지니어의 판단을 구체화합니다.
- 코딩 관련 연구 결과는 해당 실험의 범위 안에서 설명합니다. 모든 공학 직무의 효과로 확대하지 않습니다.
- 신입의 역할은 조건과 근거를 확인하고 검토를 요청하는 것부터 시작합니다. 최종 승인 책임을 신입 혼자에게 맡긴다는 뜻이 아닙니다.

## 전달할 핵심 결론

- AI로 결과를 만드는 동시에 원리를 이해하고 설명할 능력을 키웁니다.
- 자동화할 행동, 사람이 검증할 지점, 결과를 책임질 역할을 구분합니다.
- AX는 입력·실행·검토·피드백을 포함한 전체 업무 흐름의 재설계입니다.
- 성과는 검토와 재작업을 포함해 측정합니다.
- AI로 가능성을 넓히고, 원리를 배우며, 판단과 결과에 책임지는 엔지니어를 지향합니다.

### 02. 성장은 결과물이 아니라, 내 안에 남는 역량이다.
