# AI 교육자료 슬라이드 작성 가이드

> 본 가이드는 지금까지 교육자료 제작 과정에서 사용자가 직접 제시한 지시사항을 기준으로 정리한다.

---

## 1. 교육자료의 기본 방향

### 1.1 실제 사건과 스토리를 중심으로 구성
- 교육자료는 **개념 설명 중심이 아니라 실제 사건, 실제 사례, 실제 스토리 중심**으로 구성한다.
- 슬라이드에는 **실제 사건을 보여주고, 해석과 결론은 발표자가 말로 전달**한다.
- 하나의 슬라이드에 많은 정보를 넣기보다, **한 사건 또는 한 장면을 중심으로 이야기**가 진행되도록 한다.

### 1.2 텍스트보다 실제 사진을 우선
- 텍스트 중심 슬라이드는 최소화한다.
- 가능한 한 **실제 사진, 뉴스 사진, 당시 화면, 기사 캡처, 실제 서비스 화면**을 적극적으로 활용한다.
- 사진을 단순 장식 요소로 쓰지 않고, **스토리 자체를 전달하는 핵심 콘텐츠**로 사용한다.
- 설명은 발표자가 말로 할 수 있도록 하고, 슬라이드에는 필요한 내용만 남긴다.

### 1.3 부연 설명 최소화
- 슬라이드에 긴 설명문을 넣지 않는다.
- 사건명, 짧은 사실 설명, 숫자, 날짜, 출처 정도만 사용한다.
- 발표자가 설명할 내용을 슬라이드 안에 모두 적지 않는다.
- 한 장에서 보여주는 사건과 장면이 무엇인지 명확해야 한다.

### 1.4 제목과 본문에 결론을 쓰지 않는다
- 제목은 사건명, 인물, 날짜, 대국명 등 사실 중심으로 작성한다.
- 본문은 해당 사건의 상황, 참가자, 진행 방식, 결과 기록을 설명한다.
- “경계를 넘었다”, “더 중요한 것은”, “발전 속도가 빨라졌다” 같은 해석·교훈·메시지는 슬라이드에 넣지 않는다.
- 결론은 발표자가 직접 설명한다. 마지막 장도 결론 문구 대신 사건 목록 등 사실 자료로 구성한다.
- 예: “다음 경계는 언어였다” → “IBM Watson의 퀴즈쇼 출전”.

## 2. 사진 사용 원칙

### 2.1 사진을 배경으로 사용하지 않는다
- 실제 사진은 슬라이드 전체 배경 이미지로 사용하지 않는다.
- 사진은 **슬라이드 내부에 명확한 프레임을 두고 배치**한다.
- 사진과 텍스트가 서로 독립적으로 인식될 수 있도록 구성한다.

### 2.2 사진은 반드시 슬라이드 프레임 안에 들어와야 한다
- 사진이 화면 밖으로 잘리거나 슬라이드 영역을 벗어나지 않도록 한다.
- 브라우저 크기나 화면 비율이 달라져도 사진이 프레임 밖으로 나가지 않도록 한다.
- 사진의 크기와 위치를 실제 발표 화면 기준으로 검토한다.

### 2.3 원본 사진을 최대한 그대로 사용
- 가능한 한 **원본 이미지의 비율과 구도를 유지**한다.
- 불필요한 크롭, 확대, 왜곡을 하지 않는다.
- 사진의 일부를 임의로 잘라 핵심 장면이 사라지지 않도록 한다.
- 원본 비율을 유지하되, 작은 이미지가 지나치게 작게 보이지 않도록 **프레임 자체의 크기와 배치를 조정**한다.

### 2.4 이미지 비율에 맞춰 레이아웃을 다르게 설계
모든 사진을 같은 규격의 박스에 억지로 넣지 않는다.

- 가로형 사진 → 넓은 가로 프레임
- 세로형 사진 → 세로 프레임 또는 사진 중심 2단 레이아웃
- 정사각형/바둑판/도표 → 정사각형에 가까운 프레임
- 기사 캡처/UI 화면 → 전체 내용을 읽을 수 있도록 원본 비율 유지
- 여러 장 비교 → 각 이미지가 충분한 크기로 보이도록 균형 배치

### 2.5 사진이 충분히 크게 보여야 한다
- 실제 사진을 많이 사용하더라도 사진이 너무 작아져서는 안 된다.
- 한 장의 대표 사진이 있는 경우 사진이 슬라이드의 주요 면적을 차지하도록 한다.
- 여러 이미지를 넣을 때도 각 이미지를 식별할 수 있는 크기를 확보한다.

## 3. 텍스트와 사진의 배치

### 3.1 사진이 주인공, 텍스트는 보조
- 사진을 먼저 배치하고 그에 맞춰 텍스트 공간을 정한다.
- 텍스트 때문에 사진을 지나치게 줄이지 않는다.
- 사진과 텍스트의 비중을 매 슬라이드마다 검토한다.

### 3.2 사진 옆 텍스트는 짧게
권장 구조:

**[큰 사진] + [사건 설명 1개]**

또는

**[짧은 제목]**<br>
**[큰 사진]**<br>
**[날짜 / 출처 / 한 줄 설명]**

### 3.3 불필요한 카드·박스 남발 금지
- 사진 옆에 여러 개의 설명 카드가 붙으면서 화면이 복잡해지지 않도록 한다.
- 하나의 사진에는 가능하면 하나의 사건 설명만 연결한다.
- 장식적 UI보다 사건과 사진 자체가 잘 보이는 것이 우선이다.

### 3.4 페이지마다 레이아웃을 검토
자동으로 동일한 템플릿을 반복하지 않는다.

각 페이지마다 다음을 확인한다.

- 이 사진은 가로형인가, 세로형인가?
- 사진이 충분히 크게 보이는가?
- 원본이 잘리지 않았는가?
- 텍스트가 사진을 압도하지 않는가?
- 화면 중앙이나 한쪽에 과도한 빈 공간이 생기지 않는가?
- 제목과 사진의 시선 흐름이 자연스러운가?

## 4. 첫 장과 페이지 넘버링

### 4.1 챕터 첫 장
- 첫 장에는 **챕터명만 표시**한다.
- 추가 설명, 부제, 사진, 날짜 등을 넣지 않는다.

예:

# THE SPEED

### 4.2 페이지 넘버링
- 모든 본문 슬라이드에 페이지 번호를 표시한다.
- 전체 슬라이드 수와 현재 페이지를 함께 표시하는 형식을 사용할 수 있다.

예:

`03 / 18`

- 페이지 번호는 작게 표시하되, 매 슬라이드 동일한 위치를 유지한다.

## 5. 스토리 구성 원칙

### 5.1 개념보다 사건이 먼저
잘못된 방식:

> AI는 빠르게 발전했다.<br>
> AI는 멀티모달이 되었다.<br>
> AI 영상 기술이 발전했다.

권장 방식:

> Deep Blue가 Kasparov를 이긴 실제 사진<br>
> → Watson이 Jeopardy!에 등장한 실제 장면<br>
> → AlphaGo와 이세돌 대국<br>
> → 실제 생성형 AI 작품<br>
> → 실제 AI 영상 비교

### 5.2 사건의 '결정적 장면'을 찾는다
사건 전체를 설명하려 하지 말고, 청중이 기억할 장면을 고른다.

예:
- Deep Blue vs. Kasparov 대국 장면
- Watson이 Jeopardy! 무대에 선 장면
- AlphaGo 제2국 37수
- 이세돌 제4국 78수
- Midjourney 작품 `Théâtre D’opéra Spatial`
- 2018년 AI 수능 기사
- Will Smith spaghetti 초기 AI 영상
- Sora / Veo / Higgsfield 실제 결과물

### 5.3 숫자는 강한 비교에만 사용
- 숫자가 많아지면 설명 자료처럼 보이므로 최소화한다.
- 시간 변화나 성능 격차를 직관적으로 보여줄 때 사용한다.

예:
- 영어 12점 → 92점
- 수학 16점 → 82~96점
- IMO Silver → Gold
- AlphaGo Lee → AlphaGo Zero

## 7. 디자인 시 피해야 할 것

### 하지 말 것
- 사진을 풀스크린 배경으로 깔기
- 텍스트를 사진 위에 겹쳐 놓기
- 사진을 과도하게 크롭하거나 확대하기
- 모든 사진을 같은 비율의 프레임에 강제로 넣기
- 사진이 프레임 밖으로 튀어나오게 만들기
- 긴 문장과 많은 설명을 한 슬라이드에 넣기
- 사진보다 텍스트 면적이 더 커지는 구성
- 내용이 없는 장식용 카드와 박스를 많이 배치하기
- 같은 레이아웃을 모든 슬라이드에 기계적으로 반복하기
- 사진의 핵심 장면이 보이지 않을 정도로 작게 배치하기

### 반드시 할 것
- 실제 사진을 우선 사용
- 사진 원본 비율 최대한 유지
- 사진마다 적합한 프레임 설계
- 사진과 텍스트의 균형 페이지별 검토
- 사건 설명은 짧게 쓰고 결론과 메시지는 발표자가 전달
- 페이지 넘버링 적용
- 첫 장에는 챕터명만 표시
- 실제 발표 화면에서 사진이 충분히 크게 보이는지 확인

## 8. 슬라이드 제작 후 최종 QA 체크리스트

각 슬라이드를 완성한 후 아래 항목을 반드시 확인한다.

### 이미지
- [ ] 사진이 슬라이드 프레임 안에 완전히 들어와 있는가?
- [ ] 사진의 원본 비율이 유지되는가?
- [ ] 불필요한 크롭이나 확대가 없는가?
- [ ] 사진이 너무 작게 보이지 않는가?
- [ ] 사진의 핵심 인물/장면이 명확하게 보이는가?
- [ ] 사진이 단순 배경이 아니라 실제 콘텐츠로 보이는가?

### 레이아웃
- [ ] 사진과 텍스트의 비율이 자연스러운가?
- [ ] 사진의 형태에 맞는 레이아웃을 사용했는가?
- [ ] 빈 공간이 지나치게 많거나 한쪽으로 치우치지 않았는가?
- [ ] 사건명 → 사진 → 사실 설명의 시선 흐름이 자연스러운가?

### 텍스트
- [ ] 부연 설명을 최소화했는가?
- [ ] 긴 문단이 없는가?
- [ ] 슬라이드 한 장에서 다루는 사건이 명확한가?
- [ ] 제목과 본문에서 결론·해석·교훈을 제거했는가?
- [ ] 발표자가 말로 설명할 부분까지 슬라이드에 적지 않았는가?

### 전체 덱
- [ ] 실제 사건과 스토리 중심으로 이어지는가?
- [ ] 사진이 충분히 많이 활용되었는가?
- [ ] 페이지 넘버링이 일관되게 적용되었는가?
- [ ] 챕터 첫 장은 제목만 존재하는가?
- [ ] 각 페이지를 개별적으로 검토했는가?

## 9. 최종 한 줄 원칙

> **슬라이드는 설명문이 아니라, 발표자가 이야기를 시작하게 만드는 실제 장면이어야 한다.**

## 전체 챕터 구성

1. THE SPEED
2. THE QUESTION
3. THE ENGINEER
4. THE CHOICE

각 챕터 표지는 제목만 표시한다. 현재 HTML은 THE SPEED 21장, THE QUESTION 8장, THE ENGINEER 8장, THE CHOICE 5장으로 총 42장이다. THE QUESTION은 실제 외부 피해 사례와 가상 환경의 통제 실험을 구분하고, 연구진의 주장과 회사 확인 범위가 다르면 함께 명시한다.

THE ENGINEER는 직업별 업무 노출도, 관찰된 고용, 실제 개발 도구 사례, 엔지니어의 업무, BEFORE / AFTER 비교로 구성한다. THE CHOICE는 학습·업무·일상과 사람·엔지니어·구성원에 대한 질문으로 구성한다. 질문형 제목은 사용할 수 있으며 답이나 교훈을 미리 적지 않는다. 연구 결과와 가상의 토의 상황은 구분해서 표시한다.
